### T-Q3. R26: a frozen field changed to an invalid reference
"The check comes after `404` and before the reference checks of 002/R13." **Tested:** on a used article,
`PUT` with `baseUnitId` = a random UUID -> `409 IN_USE` with key `baseUnitId` (not `REFERENCE_NOT_FOUND`);
`PUT` with `type: "service"` and `name: ""` -> `400` (validation first); `PUT` on a random article id -> `404`.
Is that the intended order?

### T-Q4. Writes to the ledger over HTTP
Section 4.3 says no operation creates, changes or deletes a ledger entry. **Tested** as spec 001 (amended)
says for an unsupported method: `404 NOT_FOUND` problem. If `405` were meant here, the test must change.

### T-Q5. AC-80: what is checked beyond the criterion's words
- `lines` of `stock_document_create` / `_update`: type `array`; the item schema (directly or through a local
  `$ref`) is closed, has exactly the properties `articleId` and `quantity`, both required, and `quantity`
  allows `number` and not `string`.
- `type` (create, list) and `status` (list) are enums with exactly the values of the spec (003 §5.2 rule,
  added as cases to the existing enum test).
- `stock_document_post` has the full annotation tuple of section 5, not only the two hints the criterion names.
- The 32-name list replaced the 24-name list in the same test; no assertion was removed.

### T-Q6. Readings the tests take where a criterion leaves room
- AC-20: all fifteen properties of section 4.1 must be present and `tenantId` absent; the set is **not**
  asserted as exact (004 T-Q2 is still open). `updatedBy` on a new draft is not asserted.
- AC-30: `postedAt` must lie within a few seconds of the request.
- AC-34 is run for a posted receipt and a posted issue; "unchanged" compares the document, the whole
  stock-on-hand list and the whole ledger list before and after.
- AC-46: the seven refused responses must have the key `lines[0].quantity`; seven drafts remain.
- AC-53: the two requests use the same key.
- AC-61 "oldest first": the documents are created in the opposite order to their posting, so creation order
  cannot satisfy the test.
- AC-83, quantity `"5"`: only the code `VALIDATION_FAILED` is asserted, as the criterion says. Should the key be
  `lines[0].quantity`, as over HTTP (E3)?
- AC-91 is run for X's draft and for X's posted document, over HTTP and through tools.
