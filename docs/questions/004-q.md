### T-Q2. Representations are asserted as exact property sets
AC-20, AC-40, AC-70 and AC-77 assert that the body has **exactly** the 17 (partner) / 14 (warehouse)
properties of section 4, in addition to what the criterion lists ("all properties are always present",
"no `tenantId`"). An extra property would fail these tests.

### T-Q3. AC-91: how "string or null" is recognised in an input schema
Section 5.2 says nullable text arguments have the schema type `string` or `null`. The test accepts
`"type": ["string", "null"]` and also `anyOf` / `oneOf` alternatives that together allow both types; it checks
`taxId` and the six address arguments of `partner_create`, `partner_update`, `warehouse_create`,
`warehouse_update`. Is `anyOf` acceptable, or must it be the `type` array?

### T-Q4. AC-90 to AC-93: what changed in `McpToolListTests`
- The literal list is now 24 names (`AC40_S004_AC90_…`); there is no 14-name test any more.
- The bodies of 003/AC-41 and 003/AC-42 moved into two helpers. `AC41_…` / `AC42_…` run them over the 14
  tools of spec 003, the new `S004_AC91_…` / `S004_AC92_…` over the ten new tools, so that each criterion
  fails for its own tools. No assertion was removed or loosened.
- AC-93 is the existing tenant comparison (`AC44_S004_AC93_…`), unchanged apart from its name.

### T-Q5. Readings the tests take where a criterion leaves room
- AC-10 / AC-11 already pass before any implementation (authentication runs before routing), as 003/AC-26 did.
- AC-103 / AC-111: the data is built so that the filtered call returns one item of three matches
  (`total == 3`, the second by code); a list that ignored a filter would not be equal to this.
- AC-108: tested for `taxId` and `countryCode` as written; the other five nullable arguments are covered over
  HTTP by AC-41 (one request per field).
- AC-120, second case: besides the parity of keys, a separate test asserts that the tool error carries both
  `countryCode` and `taxId`.
- AC-121: the "equal to a following HTTP `GET`" check is included.
- AC-138: 20 calls **per tenant** (10 `partner_create`, 10 `partner_list`), 40 in flight; all partners share
  one `taxId` and the lists search for it, so a leak through the search path would show too.
- AC-134 also sends `tenantId` in a `POST /warehouses` body.
