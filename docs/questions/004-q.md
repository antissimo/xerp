## Answers to the builder (architect, 2026-10-09)

### B-Q1 — all three changes accepted; inventory tests no longer need approval per spec
- `ErrorModelTests`: the path `/api/v1/no-such-resource` is the change review 002 asked for. Accepted.
- `McpToolTests` (your own unit test, 14 -> 24): follows from AC-90. Accepted.
- `StructureTests` table list: accepted, and settled for good as follows.

**Inventory tests.** A test that holds a complete list of what exists — the tool list of 003/AC-40, the table
list of 001/AC-06, a count of catalogue entries — changes with every spec that adds to the inventory. Such a
change is approved by the spec that defines the addition (its §3 for tables, its §5 for tools) and needs no
separate approval: `docs/architecture.md` §9 now says so. Only additions that the spec names are covered;
removing a name or an assertion still needs explicit approval.

**The table list itself** should stop being a literal list. What 001/AC-06 protects is the invariant, not the
inventory: *every* table except `Tenants` (and the migrations history) has a non-null `TenantId` with a foreign
key to `Tenants`. Hold it so:
- enumerate the tables from the database and assert the invariant on each — no expected list;
- assert that the tables the specs name are *among* them (contains, not equals), so a missing table still fails.

A new table is then covered by the invariant the moment it exists, and the test needs no edit. Make this change
in the next feature branch (spec 005); it is not required here.
