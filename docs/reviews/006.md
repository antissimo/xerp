## Required changes

1. **Posting must report inactive header masters alone (005/R13 as amended, 006/R5).**
   `StockLineChecks.ActiveForPosting` now puts inactive warehouses and inactive articles into one
   `REFERENCE_INACTIVE` error (006-q, B-Q2). The spec says header before lines: inactive masters of the header
   (`warehouseId`, `toWarehouseId`) are reported together and **alone**; inactive articles
   (`lines[i].articleId`) are reported only when the header is clean, all of them together. Example: a
   transfer whose destination and one article are inactive must answer with key `toWarehouseId` only; the
   branch answers with `toWarehouseId` and `lines[0].articleId`.
   - This also changes merged behaviour: the spec 005 code on `main` returns the warehouse alone; with this
     branch a receipt or issue with an inactive warehouse and an inactive article gets both keys.
   - Cause: the rule was written into 005/R13 on `main` (`21f06ad`, answers to 005-q B-Q5 and 006-q T-Q3)
     after the branch was cut; the branch does not contain that commit. B-Q2 is answered in 006-q.
   - Wanted: warehouses first, return if any; then articles. A unit test of `ActiveForPosting` for the mixed
     case (inactive warehouse + inactive article -> warehouse key only; two inactive warehouses + article ->
     the two warehouse keys only). Do not change a tester test; none asserts the mixed case.
