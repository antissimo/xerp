## Tenant scope

- The four new entities implement `ITenantOwned`; filter, stamping and write check are applied by type in the
  DbContext, so they cannot be forgotten. Every foreign key between them and to the masters and API keys
  includes `TenantId`; all restrict deletes.
- Every query in `StockDocumentOperations` and `StockQueries` goes through the filtered `IXerpDb`. The diff
  adds no `IgnoreQueryFilters()` and no raw SQL beyond the existing tenant-lock statement, which is
  parameterised and keyed by the current tenant.
- The eight tools call the same operations as the routes; AC-90…AC-95 pass over HTTP and through tools.

## Layers

- Domain: lifecycle, signs of the entries, quantity rule, number format, sufficiency (`StockDocument`,
  `StockRules`). Application: order of checks, references, the transaction (`StockDocumentOperations`,
  `StockLineChecks`, `StockDocumentValidation`). Both unit-tested without HTTP (AC-04).
- `StockEndpoints` and the tool catalogue bind, call one operation and map the result; no rule lives there.
- One migration added (`StockLedger`), additive; no earlier migration edited (B-Q4).

## The per-tenant lock (B-Q2)

Accepted in ADR-0012's amendment; the code meets its conditions for this spec. The lock is
`FOR NO KEY UPDATE` on the tenant's row, so ordinary master writes are not blocked. Every stock document
write and the article replace run under it; each reads what it decides on after taking the lock and saves
once. Nothing slow happens inside it. No race criterion passes only by accident of the lock: they pass
because of it, which is the design.
