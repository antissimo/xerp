## What was checked

Tenant scoping
- `Partner` and `Warehouse` implement `ITenantOwned`; the filter, the stamping and the write check are applied
  by type in the DbContext, so neither could be forgotten.
- All twelve operations read and write through `IXerpDb.Partners` / `IXerpDb.Warehouses` only. Code uniqueness
  and by-code lookup are therefore per tenant; another tenant's record is `NOT_FOUND` (T2).
- No input type has a tenant field; bodies and tool arguments reject unknown properties (T4).
- `IgnoreQueryFilters()` still occurs once in `src`, in the authentication lookup (T5).
- Both tables have the alternate key `(TenantId, Id)` and tenant-inclusive audit foreign keys.

Business rules where they belong
- Optional text (R3) and country code (R4) are each one rule class in Domain (`OptionalTextRules`,
  `CountryCodeRules`), used by `Address`, `Partner` and the validation. The country pattern is `^[A-Z]{2}\z`,
  so a trailing line break cannot pass.
- The address is one Domain value type, mapped to six flat columns; on the wire it stays six top-level fields
  with plain `errors` keys.
- At least one role (R15): `PartnerRules.HasRole` in Domain, enforced by `Partner.Replace` (which `Create`
  goes through) and reported by `PartnerValidation` under both keys. An entity without a role cannot exist.
- Omitted versus `null` on replace (R7, R21) is tracked by the input type and decided in the validation.
- Order of checks is R11: validation, then the addressed record, then the code; the unique index decides races.
- Partner search is one query over code, name and tax id with escaped patterns; the address is not searched.

Thin Api and MCP
- Endpoints bind, call one operation and map the result. The ten tools are catalogue entries with a
  description, a closed schema and one call; no rule lives in either transport.
- Tool descriptions carry what §5.2 asks: the role rule and "tax id is not unique, search first" on
  `partner_create`; the form of `countryCode` on the property.

Data (AC-02)
- One migration added (`PartnersWarehouses`); earlier migrations untouched.

Logging (S2): no new log statement; request bodies, tax ids and addresses are not logged.

Earlier review items closed here: review 001 item 5 and review 002 item 3 — unique violations are now
reported by meaning (`IsCodeOf<T>()`), so Application no longer compares index names.
